# 工作室更新与宿主同步

工作室由三个部分组成：dsh Profile 加载独立插件包；共享的工作室容器和运行时提供菜单、页面与会话接口；每个工作室提供自己的页面、业务逻辑和来源声明。GitHub 仓库是源码来源，不是自动更新开关。

## 更新工作室

1. 从对应工作室仓库选择与当前 dsh、共享运行时兼容的版本，下载 Actions 产物并解压得到 `.tgz`；保留当前包以便回退。
2. 退出 dsh，备份 `DSH_HOME`。其中包含工作室配置、会话和凭据文件，应按私密数据保存，不上传 GitHub。
3. 使用当前 dsh 安装的 CLI 执行 `dsh plugin --profile desktop add <新 tgz 的绝对路径>`。源码开发环境使用 `pnpm dsh plugin --profile desktop add <路径>`。安装器报告同名条目时，先检查插件管理器中的现有条目，再更新其来源，避免重复启用两份。
4. 重新启动，检查工作室、模型选择、会话同步和所需功能。失败时退出并恢复上一个兼容包；不要用旧版本覆盖已经迁移的数据，先查看版本说明。

当前开发 Profile 使用本地链接。构建独立仓库并重启即可加载本机修改；拉取源码但没有重新构建不会更新页面产物。此方式不代表已安装的用户会自动取得新版本。

## 同步上游 dsh

本工作室插件本身不修改 dsh 核心。宿主 fork 已有悬浮球、划词、模型路由和会话等本地改动，因此上游更新可能与这些文件冲突。更新某个工作室不会同步 dsh 本体；安装官方 dsh 也不保证包含 fork 的附加功能。

先保存当前分支上的已审核改动，记录可回退版本并备份 `DSH_HOME`；在单独集成分支获取 `deepseek-ai/deepseek-harness` 的目标发布版本，审查差异并处理冲突。按照宿主升级指南执行构建和相关测试，再验证工作室注册、MCP、模型设置、历史记录与悬浮球同步。兼容验证通过后再更新当前使用的应用与插件兼容声明。

预稳定版本的插件 API 可能变化。遇到 `studioProjects`、Session、MCP 或 Shell/Jobs 接口变化，应在共享运行时或受影响插件中适配后发布新版本，不能承诺上游每次发布都能立即无修改接入。依赖锁定、独立仓库及公开接口能减少冲突，但不能消除宿主定制代码的维护工作。
